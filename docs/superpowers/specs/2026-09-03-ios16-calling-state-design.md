# iOS 16 叫号状态恢复设计

## 目标

在 iOS 16 的空配置新安装中，叫号页必须自动从初始加载态进入“暂无叫号内容”，且不依赖 SwiftUI 子视图的生命周期回调。

## 证据与根因假设

TestFlight 的 `1.0.3 (5)` 已包含三秒加载诊断，但 iPhone 8 Plus iOS 16.7.16 只显示初始转圈，诊断状态和数据状态都没有呈现。空配置排除了业务数据、面板选择和网络因素。

叫号页是唯一由 `AppRootView` 创建 `@StateObject` 后，经 `@ObservedObject` 传入子视图的主页面；正常工作的面板页则在自己的根视图中持有 `@StateObject`。当前初始加载同时依赖根/子视图的 `onAppear`。因此本次将首次加载的责任收敛到 ViewModel 本身，并使用根级 `@EnvironmentObject` 传递共享状态，避免 iOS 16 的子 Tab 生命周期和观察桥接成为正确性前提。

## 架构

`AppRootView` 继续唯一拥有 `CallingViewModel`，负责后续的前台恢复、Tab 返回和键盘行为。创建 ViewModel 时，它立即启动已有的单飞刷新任务；重复调用 `requestRefresh()` 仍被忽略。这样首次加载不依赖任何视图是否出现。

`CallingView` 不再接收依赖或 ViewModel，也不拥有 `onAppear` 刷新入口；它从环境读取同一个 `CallingViewModel`。根视图将该对象注入叫号页面所在的导航栈。工具栏继续消费同一个实例。

## 错误处理与诊断

现有诊断状态保留到本次验证完成，以便 TestFlight 仍能在刷新真正阻塞时显示阶段与重试按钮。状态加载完成、失败或任务取消时清理诊断。业务错误仍映射为既有失败态。

## 验证

先增加一个空配置的回归测试：只构造 ViewModel，不手动调用刷新，最终必须观察到 `.empty`。该测试会在实现自动启动前超时失败，随后通过。

执行 CallingViewModel 全部单元测试，并对无签名的通用 iOS Release 目标构建。由于本机没有 iOS 16 模拟器且 iPhone 8 Plus 未通过数据线接入，最终运行时确认仍需使用 TestFlight 的 `1.0.3 (6)`。

## 范围

不改 Core Data 查询、业务数据、面板数据、网络、音频和调用流程；不新增第三方依赖。发布版本保持 `1.0.3`，构建号从 `5` 增至 `6`。
